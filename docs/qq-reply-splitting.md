# QQ 回应分段（0.19.2）

QQ → NapCat → 回应分段：自动分段、分割正则、移除正则、最小/最大间隔。默认启用，分割正则 `。|`，移除正则 `。`，间隔3到5秒。

分割时保留匹配到的分隔内容，再对每段执行移除正则；最后过滤纯空白段。默认把 `你好。今天晴天。尾句` 发成 `你好`、`今天晴天`、`尾句`。第一段立即发送，相邻段间独立均匀随机等待。移除规则留空则保留分隔内容；关闭自动分段保持原始消息且不等待。

`。|` 包含空分支，因此忽略这种规则产生的零宽匹配，避免拆成单个字符；有意使用、且不匹配空字符串的零宽边界（例如 `(?<=。)`）仍可分段。捕获组不会被当作独立消息输出。

QQ 主对话回应、明确 QQ 目标的框架投递、qq_send 统一使用此发送路径。文字段落和混合消息中的文本参与分段；图片、语音、视频、@、引用等非文本片段保留原有相对顺序，不重复添加到每一段。文件上传与普通回应使用同一目标发送锁。不同目标可并行，同一目标的完整回应串行，避免分段相互穿插。

每段有独立投递记录及去重 ID，真实发送文字进入 QQ 处理后的消息列表；主对话上下文和网页仍保留完整回应，不按 QQ 分段改写。断线、取消或发送失败终止当前剩余分段；不自动重放已发送或结果不明的内容。

公共 conversation_source / delivery_adapter 新增 timeout 参数，默认仍30秒；QQ 使用 timeout=None 允许完整的分段回应，每个 NapCat 请求仍有30秒超时。其他插件保持原超时。停用 QQ 会取消进行中的发送；配置分段参数只影响之后开始的发送，不触发 NapCat 重连。

按会话要求不运行发送测试；仅执行构建与部署状态确认，不向 QQ 发送测试消息。

## 分段后整理

新增 reply_trim、reply_merge_newlines，均默认 true，可在“回应分段”中单独关闭。关闭自动分段时，两项均不改写消息。

处理顺序：正则分段 → 正则移除 → 连续换行合并 → 消息首尾裁剪。连续文本片段先拼接，兼容跨片段的连续换行；CRLF/CR 统一为 LF，连续换行（包括中间只有空白的空行）合并为一个 LF。裁剪删除每条分段消息首尾空白，保留中间空格和单次换行。混合消息的 @、图片、引用等片段顺序不变，不删除用于分隔中间非文本片段的空格。

两个规则均使用 Python re。移除通过 re.sub(pattern, '', chunk) 在每段任意位置生效。`[。*`]` 是字符集合，删除所有中文句号、字面星号和反引号；其中 * 不是通配或重复量词。这会同时删除 Markdown 加粗/斜体和代码标记，并非只处理段末符号。本次不自动更改用户现有的移除正则。
