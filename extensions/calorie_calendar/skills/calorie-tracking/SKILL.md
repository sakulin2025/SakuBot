# 热量日历

使用 `calorie_record` 添加、修改、删除记录；使用 `calorie_report` 查看当天或一段日期；使用 `calorie_confirm` 确认或取消确认。单位始终是大卡（kcal），每日仅已确认数据计入汇总。增删改记录不会改变日期的确认状态；已确认日期的统计会随记录更新。用户明确表示一天的数据已核实或要求确认时再确认，不要因为刚录入就自动确认。

记录前先查询当日记录。早餐、午餐、晚餐分别最多一条；基础代谢、活动消耗分别最多一条。餐食追加或修正时更新原条目，按用户的补充计算该餐的新总量，记录依据，避免重复计入。自定义标签可重复；不要把自定义标签冒充特殊标签。

## 餐食图片与补充

1. 用户分享食物图片并有记录或统计意图时，根据图片描述与用户文字确定日期、食物、份量和餐次。用户未说明餐次时，参考消息时间和本地时间推测早餐、午餐或晚餐，并说明是推测；不能仅凭当前时间断言照片是现在拍的。有歧义时询问。
2. 优先使用当前可用的营养识别或食物数据库工具；能可靠识别品牌、品名时，如果联网搜索可用且有助于精度，可检索品牌官方营养成分表。区分每 100 克、每份和整包的单位，按实际份量换算；不能把类似商品的表当成确定的官方数据。
3. 没有更准确工具时按可见食物和合理份量独立估算，明确大致值与主要假设。照片无法确定的油、酱、重量和份量不要假装知道；差异较大时向用户询问。无法看见或描述图片时，不编造图中食物。
4. 记录使用 `estimated=true`，`note` 记录具体食物、份量及主要假设；追加餐食时合并保留原有食物详情，`source` 写图片估算、用户说明或官方营养表等；官方按确定份量计算且数据可靠时可使用 `estimated=false`。如有来源链接可记录在 `source` 或 `note`。后续用户更正后修改原记录，不另建重复餐次。

## 每日消耗

优先检查已启用的健康、运动或设备工具，获取该日期明确标注的基础代谢或静息能量。核实日期、单位以及是当日数据还是其他时间的估计。只拿到活动热量时记入“活动消耗”，不要说成基础代谢；若拿到总消耗，不能直接再与基础代谢和活动消耗相加，避免重复。没有可信数据时向用户询问或明确未获取，不编造。可从用户提供的数值单独记录，并注明来源。

餐次日期、份量、品牌或消耗数据不确定时如实说明；不要把这些估计当成医疗诊断或精确测量。
