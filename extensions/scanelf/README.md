# ScanElf

设备查询、上下线时间线和本地别名/描述继续使用 ScanElf 原生 HTTP API，连接配置只需 URL 和 Token。

## 设备实时触发

脚本触发源 `scanelf.device_state_changed` 使用同一地址上的 `/api/v1/ws`，HTTP 自动转为 WS，HTTPS 自动转为 WSS。通过 `Authorization: Bearer …` 鉴权，不将令牌放入 URL 或日志。反向代理部署需要允许该路径的 WebSocket Upgrade，服务端需提供原生状态流接口。

绑定可选设备 MAC 和 `any / online / offline`。所有绑定共享一条连接，由框架筛选和分发；最后一个绑定停用、删除，或插件卸载时关闭连接。保存连接设置后立即重连，不等待下一次消息。

首个可靠快照只建立基线，之后按 MAC 比较已知设备的在线状态，真正变化时才触发。名称、别名、描述等附在事件 `device` 中；普通心跳和属性变化不会触发。新设备、被忽略设备或不在快照中的设备不会凭空补造上下线变化。下线沿用 ScanElf 服务端的宽限期，不因 WebSocket 断开直接判定下线。

Scanner 断连或上游观测超过 60 秒时停止判断；恢复或重新连接后重建基线，不将缺口猜成连续的上下线事件。WebSocket 最长等待 45 秒，失败后按 5、10、20、40、80、120 秒退避重连，稳定连接满 60 秒后重置退避；连接和错误日志限频。

原生 WS 单帧最多包含 500 台设备。仅在变化快照被截断时，通过分页 HTTP 补齐当前设备列表；不是定时轮询，也不把缺失条目当作下线。事件来自状态快照比较，极短时间内的多次变化可能被服务端合并；要查询完整已记录历史，使用 `scanelf_device_timeline`。

触发只执行绑定脚本，不自动向主上下文注入数据；是否通知或唤醒智能体由脚本和失败策略决定。现有触发源 ID、参数和绑定保持兼容。
