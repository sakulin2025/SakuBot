# 创建和维护团队 Agent

成员是可重复使用的单例，不是一次性任务。创建、编辑通过专业团队工具即时生效，不要通过重载插件、修改运行设置或重启框架来刷新成员。

1. 先调用 `team_members` 查看名称、职责、状态，优先复用合适成员。临时要求通过 `team_delegate` 的 goal/context 传入，不要每次都创建新成员或修改人格。
2. 确实需要长期专业角色时，调用 `team_create_member`，提供 name、description、prompt。prompt 定义长期职责、工作方式、完成标准、协作方式；不要把用户的单次任务或不可信资料写成长期指令。
3. 默认不传 model_id，继承框架默认模型；需要指定时只用已知的框架模型条目 ID，不要编造模型名称充当 ID。
4. visible_plugins 不传或 null 表示全部插件；指定数组时使用真实插件 ID，空数组表示不提供插件工具。若成员需要团队报告、待确认、工作空间和技能，分别包含 `team`、`workspace`、`skills`。这些只是人格的工具可见性，不是新增授权流程。
5. 使用创建结果中 `agent.id` 的完整 ID 调用 `team_delegate`，提供当前任务。成员创建后立即可以委派，其余成员继续工作。
6. 调整现有成员前调用 `team_get_member` 读取完整配置，然后用 `team_update_member` 只传需要变更的字段。成员人格固定为自管理，直接通过 prompt 和 visible_plugins 编辑，不提供人格来源或人格库引用选项。

人格内容和可见插件由专业团队自己保存，再通过 Agent 实例的 set_persona、with_plugins 方法提供运行配置；声明和核心 Agent 管理不包含人格正文，自管理人格没有核心人格覆盖入口。model_source 为 override 时表示模型存在人工覆盖，插件编辑不会撤销模型覆盖。报告实际生效状态，不声称尚未生效的编辑已经改变当前任务。

人格、可见插件、模型变更从该成员下一次任务启动时生效。正在运行的任务继续使用原配置，已有上下文保留。只有明确需要重新开始时才清空或重置该成员。不要删除并重建正在执行任务的成员，也不要无必要地递归创建成员。
